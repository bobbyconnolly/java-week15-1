Using Interfaces to Swap Database Implementations 🔄

In our College Manager application, we've implemented a data access layer using H2 database. But what happens when requirements change and we need to switch to a different database system? Maybe we need to migrate to MySQL or PostgreSQL for production deployment, or SQLite for a lightweight solution.

The Power of Interfaces: One of the greatest strengths of Java is the ability to define behavior through interfaces, allowing us to easily swap implementations without changing our application code.

Understanding the Current Architecture 🏗️

Let's review how our College Manager application is currently structured:

  1. Model Classes: Student, Course - define our core business entities
  2. DAO Interfaces: StudentDAO, CourseDAO, RegistrationDAO - define database operations
  3. H2 Implementations: StudentDAOImpl, CourseDAOImpl, RegistrationDAOImpl - implement DAOs for H2 database
  4. DAO Factory: Creates and returns DAO implementations
  5. Web Layer: Servlets and JSPs that use the DAOs through their interfaces
Key Insight: Because our web application only interacts with the DAO interfaces (not the implementations), we can swap out the underlying database without changing any application code! 🔄

The DAO Pattern Revisited 📝

The Data Access Object (DAO) pattern is all about separating how we access data from how we manipulate it in our application. Let's look at one of our current interface definitions: 

public interface StudentDAO {
    
    /**
     * Find a student by ID
     * @param id the student ID
     * @return the student or null if not found
     */
    Student findById(int id);
    
    /**
     * Get all students
     * @return list of all students
     */
    List<Student> findAll();
    
    /**
     * Save a student (insert if new, update if existing)
     * @param student the student to save
     * @return true if successful
     */
    boolean save(Student student);
    
    /**
     * Delete a student
     * @param id the student ID
     * @return true if successful
     */
    boolean delete(int id);
}

Our interface defines what operations can be performed, but not how they are implemented. This is perfect for swapping databases!

Step 1: Create a Database Configuration Manager 🔧

First, let's create a configuration class that will let us choose which database to use: 

package com.example.collegemanager.db;

public class DBConfig {
    
    // Available database types
    public enum DatabaseType {
        H2,
        MYSQL,
        POSTGRESQL,
        SQLITE
    }
    
    // Default to H2
    private static DatabaseType databaseType = DatabaseType.H2;
    
    /**
     * Set the database type to use
     * @param type the database type
     */
    public static void setDatabaseType(DatabaseType type) {
        databaseType = type;
        System.out.println("Database type set to: " + type);
    }
    
    /**
     * Get the current database type
     * @return the current database type
     */
    public static DatabaseType getDatabaseType() {
        return databaseType;
    }
    
    /**
     * Get the JDBC URL for the current database type
     * @return the JDBC URL
     */
    public static String getJdbcUrl() {
        switch (databaseType) {
            case H2:
                return "jdbc:h2:~/collegemanager;DB_CLOSE_DELAY=-1";
            case MYSQL:
                return "jdbc:mysql://localhost:3306/collegemanager";
            case POSTGRESQL:
                return "jdbc:postgresql://localhost:5432/collegemanager";
            case SQLITE:
                return "jdbc:sqlite:collegemanager.db";
            default:
                throw new IllegalStateException("Unsupported database type: " + databaseType);
        }
    }
    
    /**
     * Get the JDBC driver class for the current database type
     * @return the JDBC driver class name
     */
    public static String getDriverClassName() {
        switch (databaseType) {
            case H2:
                return "org.h2.Driver";
            case MYSQL:
                return "com.mysql.cj.jdbc.Driver";
            case POSTGRESQL:
                return "org.postgresql.Driver";
            case SQLITE:
                return "org.sqlite.JDBC";
            default:
                throw new IllegalStateException("Unsupported database type: " + databaseType);
        }
    }
    
    /**
     * Get the database username
     * @return the username
     */
    public static String getUsername() {
        switch (databaseType) {
            case H2:
                return "sa";
            case MYSQL:
            case POSTGRESQL:
                return "collegeadmin";
            case SQLITE:
                return ""; // SQLite doesn't use username/password
            default:
                throw new IllegalStateException("Unsupported database type: " + databaseType);
        }
    }
    
    /**
     * Get the database password
     * @return the password
     */
    public static String getPassword() {
        switch (databaseType) {
            case H2:
                return "";
            case MYSQL:
            case POSTGRESQL:
                return "password123"; // In a real app, use a secure way to store this
            case SQLITE:
                return "";
            default:
                throw new IllegalStateException("Unsupported database type: " + databaseType);
        }
    }
}
Configuration Approach: This class centralizes all database configuration information. By changing a single setting, we can switch which database the entire application uses.

Step 2: Update the Database Utility Class ⚙️

Next, let's modify our DbUtil class to use the configuration manager: 

package com.example.collegemanager.db;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;

public class DbUtil {
    
    // Static block to load the JDBC driver
    static {
        try {
            Class.forName(DBConfig.getDriverClassName());
            System.out.println("JDBC driver loaded successfully: " + DBConfig.getDriverClassName());
        } catch (ClassNotFoundException e) {
            System.err.println("JDBC Driver not found: " + DBConfig.getDriverClassName());
            e.printStackTrace();
        }
    }
    
    /**
     * Get a database connection
     * @return a new database connection
     * @throws SQLException if connection fails
     */
    public static Connection getConnection() throws SQLException {
        return DriverManager.getConnection(
            DBConfig.getJdbcUrl(), 
            DBConfig.getUsername(), 
            DBConfig.getPassword()
        );
    }
    
    /**
     * Close a connection quietly (without throwing exceptions)
     * @param connection the connection to close
     */
    public static void closeQuietly(Connection connection) {
        if (connection != null) {
            try {
                connection.close();
            } catch (SQLException e) {
                System.err.println("Error closing connection: " + e.getMessage());
            }
        }
    }
}
Notice: We no longer hardcode the JDBC URL, driver class, username, or password in the DbUtil class. Instead, we get these values from our configuration manager.

Step 3: Create Schema Initializers for Different Databases 📋

Different databases may have slight syntax differences in their SQL DDL statements. Let's create schema initializers for each database type: 

package com.example.collegemanager.db;

import java.sql.Connection;
import java.sql.SQLException;

public interface SchemaInitializer {
    /**
     * Initialize the database schema
     * @throws SQLException if an error occurs
     */
    void initializeSchema() throws SQLException;
    
    /**
     * Create a schema initializer for the current database type
     * @return a SchemaInitializer implementation
     */
    static SchemaInitializer create() {
        switch (DBConfig.getDatabaseType()) {
            case H2:
                return new H2SchemaInitializer();
            case MYSQL:
                return new MySQLSchemaInitializer();
            case POSTGRESQL:
                return new PostgreSQLSchemaInitializer();
            case SQLITE:
                return new SQLiteSchemaInitializer();
            default:
                throw new IllegalStateException("Unsupported database type: " + DBConfig.getDatabaseType());
        }
    }
}

Now, let's implement the H2 version of the schema initializer: 

package com.example.collegemanager.db;

import java.sql.Connection;
import java.sql.SQLException;
import java.sql.Statement;

public class H2SchemaInitializer implements SchemaInitializer {

    @Override
    public void initializeSchema() throws SQLException {
        Connection conn = null;
        try {
            conn = DbUtil.getConnection();
            
            // Create tables
            Statement stmt = conn.createStatement();
            
            // Create students table
            stmt.execute(
                "CREATE TABLE IF NOT EXISTS students (" +
                "  id INT PRIMARY KEY, " +
                "  name VARCHAR(100) NOT NULL, " +
                "  email VARCHAR(100) NOT NULL UNIQUE" +
                ")"
            );
            
            // Create courses table
            stmt.execute(
                "CREATE TABLE IF NOT EXISTS courses (" +
                "  code VARCHAR(10) PRIMARY KEY, " +
                "  title VARCHAR(100) NOT NULL, " +
                "  credits INT NOT NULL, " +
                "  instructor VARCHAR(100) NOT NULL" +
                ")"
            );
            
            // Create registrations table
            stmt.execute(
                "CREATE TABLE IF NOT EXISTS registrations (" +
                "  student_id INT, " +
                "  course_code VARCHAR(10), " +
                "  PRIMARY KEY (student_id, course_code), " +
                "  FOREIGN KEY (student_id) REFERENCES students(id) ON DELETE CASCADE, " +
                "  FOREIGN KEY (course_code) REFERENCES courses(code) ON DELETE CASCADE" +
                ")"
            );
            
            System.out.println("H2 database schema setup complete!");
            
        } finally {
            DbUtil.closeQuietly(conn);
        }
    }
}

And here's a SQLite version, which has some syntax differences: 

package com.example.collegemanager.db;

import java.sql.Connection;
import java.sql.SQLException;
import java.sql.Statement;

public class SQLiteSchemaInitializer implements SchemaInitializer {

    @Override
    public void initializeSchema() throws SQLException {
        Connection conn = null;
        try {
            conn = DbUtil.getConnection();
            
            // Enable foreign keys in SQLite (they're off by default)
            Statement pragmaStmt = conn.createStatement();
            pragmaStmt.execute("PRAGMA foreign_keys = ON");
            
            // Create tables
            Statement stmt = conn.createStatement();
            
            // Create students table
            stmt.execute(
                "CREATE TABLE IF NOT EXISTS students (" +
                "  id INTEGER PRIMARY KEY, " +  // INTEGER instead of INT
                "  name TEXT NOT NULL, " +     // TEXT instead of VARCHAR
                "  email TEXT NOT NULL UNIQUE" +
                ")"
            );
            
            // Create courses table
            stmt.execute(
                "CREATE TABLE IF NOT EXISTS courses (" +
                "  code TEXT PRIMARY KEY, " +  // TEXT instead of VARCHAR
                "  title TEXT NOT NULL, " +
                "  credits INTEGER NOT NULL, " +
                "  instructor TEXT NOT NULL" +
                ")"
            );
            
            // Create registrations table
            // SQLite has different foreign key syntax
            stmt.execute(
                "CREATE TABLE IF NOT EXISTS registrations (" +
                "  student_id INTEGER, " +
                "  course_code TEXT, " +
                "  PRIMARY KEY (student_id, course_code), " +
                "  FOREIGN KEY (student_id) REFERENCES students(id) ON DELETE CASCADE, " +
                "  FOREIGN KEY (course_code) REFERENCES courses(code) ON DELETE CASCADE" +
                ")"
            );
            
            System.out.println("SQLite database schema setup complete!");
            
        } finally {
            DbUtil.closeQuietly(conn);
        }
    }
}
Notice the differences: SQLite uses different data types (TEXT instead of VARCHAR, INTEGER instead of INT) and requires a special PRAGMA statement to enable foreign key constraints. These differences highlight why we need separate initializers for each database type.

Step 4: Create DAO Implementations for Different Databases 💻

Now let's look at creating a DAO implementation for a different database type. Let's use SQLite as an example: 

package com.example.collegemanager.dao.impl;

import com.example.collegemanager.dao.StudentDAO;
import com.example.collegemanager.db.DbUtil;
import com.example.collegemanager.model.Student;

import java.sql.*;
import java.util.ArrayList;
import java.util.List;

public class SQLiteStudentDAOImpl implements StudentDAO {

    @Override
    public Student findById(int id) {
        Connection conn = null;
        try {
            conn = DbUtil.getConnection();
            PreparedStatement stmt = conn.prepareStatement("SELECT * FROM students WHERE id = ?");
            stmt.setInt(1, id);
            
            ResultSet rs = stmt.executeQuery();
            if (rs.next()) {
                String name = rs.getString("name");
                String email = rs.getString("email");
                return new Student(id, name, email);
            }
            return null;
        } catch (SQLException e) {
            System.err.println("Error finding student: " + e.getMessage());
            return null;
        } finally {
            DbUtil.closeQuietly(conn);
        }
    }

    @Override
    public List<Student> findAll() {
        List<Student> students = new ArrayList<>();
        Connection conn = null;
        try {
            conn = DbUtil.getConnection();
            Statement stmt = conn.createStatement();
            ResultSet rs = stmt.executeQuery("SELECT * FROM students");
            
            while (rs.next()) {
                int id = rs.getInt("id");
                String name = rs.getString("name");
                String email = rs.getString("email");
                students.add(new Student(id, name, email));
            }
        } catch (SQLException e) {
            System.err.println("Error finding all students: " + e.getMessage());
        } finally {
            DbUtil.closeQuietly(conn);
        }
        return students;
    }

    @Override
    public boolean save(Student student) {
        Connection conn = null;
        try {
            conn = DbUtil.getConnection();
            
            // SQLite doesn't support MERGE or UPSERT like H2 does, so we need to do this differently
            // Check if student exists
            PreparedStatement checkStmt = conn.prepareStatement("SELECT COUNT(*) FROM students WHERE id = ?");
            checkStmt.setInt(1, student.getId());
            ResultSet rs = checkStmt.executeQuery();
            rs.next();
            int count = rs.getInt(1);
            
            PreparedStatement stmt;
            if (count > 0) {
                // Update existing student
                stmt = conn.prepareStatement("UPDATE students SET name = ?, email = ? WHERE id = ?");
                stmt.setString(1, student.getName());
                stmt.setString(2, student.getEmail());
                stmt.setInt(3, student.getId());
            } else {
                // Insert new student
                stmt = conn.prepareStatement("INSERT INTO students (id, name, email) VALUES (?, ?, ?)");
                stmt.setInt(1, student.getId());
                stmt.setString(2, student.getName());
                stmt.setString(3, student.getEmail());
            }
            
            int result = stmt.executeUpdate();
            return result > 0;
        } catch (SQLException e) {
            System.err.println("Error saving student: " + e.getMessage());
            return false;
        } finally {
            DbUtil.closeQuietly(conn);
        }
    }

    @Override
    public boolean delete(int id) {
        Connection conn = null;
        try {
            conn = DbUtil.getConnection();
            PreparedStatement stmt = conn.prepareStatement("DELETE FROM students WHERE id = ?");
            stmt.setInt(1, id);
            int result = stmt.executeUpdate();
            return result > 0;
        } catch (SQLException e) {
            System.err.println("Error deleting student: " + e.getMessage());
            return false;
        } finally {
            DbUtil.closeQuietly(conn);
        }
    }
}
Notice: The SQLite implementation is very similar to the H2 implementation, but with subtle differences in how certain operations are handled. SQLite may have different query syntax for certain operations or handle transactions differently.
